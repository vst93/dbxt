# dbxt

**English** | [中文](README.zh-CN.md)

A keyboard-first terminal UI for databases, built on the [DBX](https://github.com/t8y2/dbx) kernel. Configure a connection once — in DBX Desktop, the DBX CLI, or dbxt itself — then use it from any terminal. One static binary: no desktop app, no daemon, no HTTP server.

## 30-second quick start

1. Run `dbxt`, then `↑` `↓` + `Enter` to pick a connection (`c` creates one).
2. `↑` `↓` + `Enter` opens a table; just type in the sidebar to filter.
3. `Tab` to the SQL editor, type a statement, then `Ctrl-J` (caret statement) or `F5` (whole script).
4. In the results pane `e` edits a cell, `i` inserts, `Delete` removes — the full SQL is shown before anything runs.
5. `?` opens a cheat-sheet for the current pane, `F1` the full key list.
6. The top line of the connection list is the day's tip — press `T` for the next one.

## What's new in 0.0.4

The biggest jump since the first preview — the sidebar became a real tree, and the safety net around production connections grew up.

- **Connection tree** — the sidebar is now `connection → database → table`, foldable with `h`/`l` and remembered per session (`3j`/`3k` count-prefix moves included).
- **Desktop groups** — DBX Desktop's connection groups mirror into the tree as `▾ name [n]` nodes.
- **Status dots + manual disconnect** — every root carries `●` live / `○` disconnected / `◐` connecting; `x` drops its pools behind a red confirmation (config untouched).
- **Read-only connections** — one `read_only` flag refuses every write statement at a single choke point, while `SELECT` / `SHOW` / `EXPLAIN` still run.
- **History direct-run + favourites** — `Alt-H` recalls, `Ctrl-Enter` / `p` reruns, `f` pins a favourite section above the list; this session's runs float to the top with a cyan `●` (in-memory LRU 20, zero queries, never persisted).
- **Pinned results** — `Alt-F` snapshots the grid into a strip so you can compare across tables.
- **Context-scoped completion** — `Alt-/` offers only tables after `FROM` / `JOIN`, only columns after `WHERE` / `ON` / `SELECT`.
- **Double-click row detail** — a second click opens the row popup; confirmation buttons and tree expanders are clickable too.
- **Auto-hiding scroll bar** — the horizontal bar appears for ~2.5 s after a scroll, then the border returns to a plain line.
- **Quick database switch** — `d` switches MySQL databases, PostgreSQL schemas→databases, MongoDB databases and Redis logical DBs in one gesture.
- **Statement stepping** — `Alt-↓`/`Alt-↑` walk a multi-statement script one statement at a time (semicolon bounds, literals/comments skipped), with a `statement i/n` anchor in the status bar.
- **Per-column result filter** — `*` in the results pane keeps only the rows whose focused column contains a value (pre-filled from the cell), on top of the whole-row `/` search.
- **Server version and connect latency in the status bar** — the active connection's server version is read once on connect (a single free metadata query) and shown when the terminal is ≥56 columns wide; the duration of that same read is shown next to it as a muted `12ms` (or `1.2s`), so a slow link is obvious. A failed probe shows nothing — no error, no second query. With a table open, the status bar's context block also leads with the current `db.table` (a narrow terminal < 56 columns keeps just the table name).
- **Find inside the result cells (`\`).** `\` in the results pane searches a term across **every cell of the loaded page** and lights up each match (the current one in the accent colour); `Enter` / `n` step forward, `Shift-N` back (both wrap), and `Esc` clears. Unlike `/` (which hides non-matching rows) it never filters — the grid stays put — and unlike `g v` it scans **all** columns, not just the sort / primary key. Pure client-side over the already-loaded page (**zero queries**), capped at 500 matches (`DBXT_CELL_FIND_LIMIT` overrides).
- **Matching-bracket highlight** — with the caret on `(`/`)`/`[`/`]`/`{`/`}` (or right after it, the same rule `%` uses), the match is highlighted automatically in cyan + bold; it is **lexer-aware** (the `%` tokenizer is reused: brackets inside string literals / comments never pair) and only **±200 lines** around the caret are scanned, so a large file costs the same per frame as a one-line query. No key, no query, pure rendering.
- **Copy one cell** — `Y` in the results pane copies the focused cell's value (the status bar names the column, the value and the char count, e.g. `✓ Copied [name] = seven · 5 chars`); `y` still copies the whole row as an `INSERT`, and `y` / `Y` inside the `Enter`/`o` row popup are the same “copy value” gesture. Redis value grids and MongoDB document grids support `Y` too.
- **Sidebar quick search** — `f` searches connection / database / table names across groups from the **loaded tree cache only** (no query). Hit groups auto-expand, `Enter` jumps to the first hit and clears the needle, `Esc` just clears; the cursor sits on the first hit while you type.
- **Rename & reorder the tree.** `r` on a connection root or a group row renames it **in place** (Enter saves, Esc cancels; empty / over-long names are rejected). A connection rename is a single-row store upsert, so its pool and secrets are untouched. `Shift`+`↑`/`↓` moves a connection or group one slot up/down within its level and writes the new order back into the desktop `sidebar_layout`. `<`/`>` narrow / widen the focused result column, remembered for the session (page turns / re-runs keep it, nothing is persisted).
- **Quoted completion** — `Alt-/` quotes a table / column name only when it needs it (uppercase, punctuation or a reserved word like `order` / `key`), using the active connection's dialect: MySQL-family backticks, SQL Server brackets, otherwise double quotes. Plain lowercase names stay bare.
- **Read-only, visible everywhere** — a read-only connection shows its 🔒 on the editor title and the status-bar badge too (not only the tree root), and a refused write names the connection, e.g. `✗ Read-only connection “prod”: write statement refused (DELETE)`.
- **Column popup: defaults, key marks, in-place filter.** `g c` now adds each column's **default value** (`=CURRENT_TIMESTAMP`) and its **key** shorthand — `PRI` / `UNI`, plus `MUL` for the first column of a non-unique index (from the table's cached index metadata; the popup itself is still **query-free**). It widens to 96 columns on a large terminal; on a phone the column name / type / key stay readable and the default clips. `/` filters the list by name as you type (Enter keeps the needle, Esc clears it), so the right column in a 40-column table is one keystroke away; `j` / `k` highlight a column and `Enter` jumps the grid to it.
- **The caret's statement stands out.** In a multi-statement editor the statement under the caret keeps full brightness while every other statement is dimmed (`;` bounds; literals / comments never split — the same splitter `Alt-↓` uses). Pure rendering, no query; under 256 KiB the whole buffer is split per frame, above it only ±500 lines around the caret.
- **Jump to a row (`:`).** `:` in the results pane opens a one-line prompt: a 1-based row number (`:40`) or `$` for the last row, then Enter. It works on a query result, a browsed table and the Redis / MongoDB grids, alongside the existing `gg` / `G` / `Home` / `End` motions. An out-of-range number now **clamps to the last row** instead of reporting, and on a **paginated table view the number is an absolute table row** — the target page is loaded on demand and the cursor lands on the right offset.
- **Open a SQLite file in one key (`L`).** From the connection picker (or any browse pane) `L` opens a file picker over the current directory: type a path, `↑`/`↓` to walk the listing, `Tab` to complete a name (a single match fills it, several fill the common prefix), `Enter` to open. Sub-directories descend in place; only `.db` / `.sqlite` / `.sqlite3` files are listed. The last five files sit at the top of the picker for a one-Enter reconnect, and `Del` forgets one. Opening builds a **session-only** SQLite connection — it shows in the connection list for the rest of the run but is **never written to the connection store**, so a restart leaves no ghost connection. Everything is client-side; the only query is the one you run afterwards.
- **SQL favourites, curated (`Ctrl-O` / `Alt-S`).** `Alt-S` in the editor saves the current SQL as a DBX `saved_sql_files` favourite in one step (the same store the `Ctrl-O` list reads). The list now filters (`/`, matching the name or the SQL text case-insensitively), deletes behind a red confirmation (`d` / `Del`), and caps at **100** favourites per connection — a save past the cap is refused with a “delete some first” hint instead of growing without bound, and the empty state says how to add one. Bare `f` stays an ordinary SQL character; the editor gesture is `Alt-S`.
- **Built-in SQL templates (`Alt-T` in the editor).** With the editor focused, `Alt-T` opens a read-only panel of eight common statements — `SELECT … WHERE`, `INSERT`, `UPDATE … WHERE`, `DELETE … WHERE`, `CREATE INDEX`, `ALTER TABLE … ADD COLUMN`, `TRUNCATE`, `DROP TABLE` — and `Enter` inserts the one under the cursor at the caret. Each carries `{{table}}` / `{{col}}` / `{{value}}` placeholders: the caret lands on the first one **selected**, so typing replaces it, and `Tab` walks to the next (wrapping). The placeholders are painted in a distinct colour while they remain; once the last one is filled, `Tab` goes back to pane switching. `/` filters the list by label or SQL text, and the panel header spells out the division: these are built-in and read-only, while your own saved SQL lives in the `Ctrl-O` favourites. Insertion is pure text — **no connection, no query** (it works on a read-only connection). Outside the editor `Alt-T` stays the data-transfer wizard.
- **Skip the blanks (`}` / `{`).** In the results pane `}` / `{` move the row cursor to the next / previous row whose cell in the focused column is non-blank, skipping `NULL` and empty strings — a sparse column is otherwise a wall of blanks. The status line reports the absolute row number; `n` / `p` keep their page-turn meaning.
- **Find inside the editor (`Ctrl-F`).** `Ctrl-F` opens a bottom-bar input and searches the SQL buffer as you type — case-insensitive substring, **entirely client-side (no query)**. Every match is highlighted and the status bar carries a live `3/7` count; `Enter` / `F3` / `Alt-N` step to the next match (wrapping), `Alt-B` (or `Shift-Enter` / `Shift-F3` where the terminal reports them) to the previous. `Esc` closes the input but **keeps the highlight**, so you can keep reading; `F3` / `Alt-N` still cycle, and the next edit (typing, paste, a snippet insert) clears it. Tabs and wide CJK characters highlight their real screen cells, and the match the caret jumped to gets the accent colour so the count and the screen agree.
- **Half-page scroll (`Ctrl-D` / `Ctrl-U`).** `Ctrl-D` scrolls the editor half a screen down and the caret follows the viewport; `Ctrl-U` scrolls the results pane half a screen up, reusing the full-page (`PageUp` / `PgDn`) arithmetic so it carries across pages and clamps at the edges. The motion **yields to the documented bindings**: `Ctrl-U` stays undo in the editor and, **inside row-select mode, becomes batch set-value** (see below), while `Ctrl-D` stays delete-row in the results pane (the status line is untouched), so each pane takes the free key. Pure client-side; the results grid header stays pinned at the top of the pane while the rows scroll under it.
- **Switch tables in the same database (`g b`).** In the data view, `g b` opens a **type-to-filter** table switcher (same look as the recent-tables overlay): just type to narrow the current database's tables (matching the qualified `schema.table`, so `inv.` keeps a whole schema), `↑` / `↓` (or `j` / `k`) to choose, `Enter` to open that table's data, `Esc` to close. The list comes from the sidebar's **already-cached** table list (**zero queries**); views keep the sidebar's `~` suffix, and an active sidebar `/` filter never hides a table from it.
- **`g c` Enter jumps to the column.** Inside the column-structure popup, `j` / `k` highlight a column and `Enter` moves the results pane's cell cursor to it and closes the popup (the status bar reports `jumped to column N`). A column hidden by the column picker (or absent from a query result) reports instead of jumping somewhere wrong; the popup itself is still **zero-query**.
- **Column value distribution in `g c`.** The column-structure popup now shows the highlighted column's distribution from the **already-loaded page** — non-null / null / distinct counts, a **12-cell block sparkline** of the sampled values (a numeric histogram for a numeric column, a value-length histogram otherwise; hidden below 56 columns), and for a numeric column `min` / `max` / `avg`. It sits in a right pane beside the column list on a wide terminal and stacks under the list on a phone. Everything is computed **in place, never a query**: with no table data open it says “available after opening table data”, and a page larger than 5,000 rows is sampled to its first 5,000 with an explicit `(stats over the first N rows)` note.
- **`db.table` in the status bar.** With a table open, the status bar's context block leads with the current location — `db.table`, with the schema folded in when it differs from the database (PostgreSQL: `db.schema.table`) and skipped when it duplicates it (MySQL). The connection name already leads the left block, so only the location is added here; below 56 columns it collapses to the bare table name so the row / column readout survives.
- **Row-detail popup, one key deeper.** `o` / `Enter` already listed every column as `name = value`; now `n` / `p` move the selection inside the popup (a count prefix works, `5n`), `/` filters by **column name *or* value** as you type, and `y` / `Y` both copy the selected field's value (the status names the column and the char count — the same path as the grid's `Y`). On a narrow terminal (< 56 columns) each field stacks as `field:` above its indented value instead of squeezing the name and value onto one line. All client-side, zero queries.
- **`z` speaks everywhere.** Pinning the first column (`z`) now flashes the same bilingual state (`first column pinned · z to unpin` / `unpinned · z to pin`) in the Redis value and MongoDB document grids too — previously only the SQL result grid said anything, and MongoDB had no `z` binding at all.
- **Column widths stick.** `<` / `>` in the results pane narrow / widen the focused column; on a browsed table the width is now **written to `~/.config/dbxt/tui.json`** under `(connection, db, schema, table, column)` and restored the next time you open that table (a plain query result stays session-only). `0` drops the focused column's memory, back to its natural, content-sized width; `Alt-0` forgets **every** remembered width for the current table. The list is capped at **200** entries with LRU eviction, so a long-lived config never grows without bound.
- **Content auto-fit widths (`g w` / `g W`).** `g w` fits the focused result column to its loaded content in one keystroke: it scans the cells already in memory (**zero queries**), takes the **95th percentile** display width (so one huge outlier — a memo, a JSON blob — never stretches the column), counts multibyte / wide characters at their terminal cells, and clamps to **6–40 cells**. `g W` does the same for every visible column (including a pinned first column); on a narrow (< 80 col) terminal only the **leading visible columns** are fitted so a phone grid keeps its layout. The width goes through the same memory a manual `<` / `>` uses — a browsed table persists it, a query result stays session-only. `0` resets the column, `Alt-0` clears the table.
- **Jump to a table from the tree (`g t`).** In the sidebar `g t` opens the current database's table switcher (the same **type-to-filter** overlay as the data view's `g b`): type a table-name prefix to narrow, `↑` / `↓` (`j` / `k`) to choose, `Enter` to open it, `Esc` to close. The list is the sidebar's **already-cached** table list — **zero queries**.
- **Connection-tree quick actions.** The tree's type-to-filter (`/`, or just typing) now resolves in one step: `Enter` jumps to the first match and **acts** on it — a matched connection switches, a database switches, a table opens — and a miss shows a bilingual status hint instead of doing nothing. `Alt-Shift-H` opens the **recent-connection list** (the connections used this session, up to 8, most recent first; `↑` / `↓` + `Enter` reconnects, `Esc` closes), and `P` on a connection root / database / table row sends **one minimal health probe** (`SELECT 1` / `PING` / `db.runCommand({ping:1})`) whose RTT (or failure reason) lands on the status bar — a failure never pops an error box. Sidebar **group fold state** is now written to `tui.json` and restored on the next launch.
- **Latency at a glance on the connection tree.** Every connection root that has been probed this session shows its cached RTT as a muted tail beside the name (`accounts · 23ms`), a link that failed or timed out reads `· timeout`, and one never probed shows nothing — a pure read of the R63 session cache, **zero queries**, and visible on a narrow sidebar too (it no longer borrows the right-aligned size column). `Ctrl-P` on the connection panel probes **every saved connection at once** (at most 4 in flight, 3 s each): the tree tails and the status-bar progress (`Probing 3/8`) update as each packet lands, and the summary reads `8 total · 7 up · 1 timed out`. Once something has been probed, `O` re-sorts the tree by cached latency ascending (never-probed last, a stable sort) and `O` again restores the original order — session-only, never written to config. The probe is an explicit keystroke, never a background poll; in the editor `Ctrl-P` stays `EXPLAIN`, since only one pane owns the keyboard at a time.
- **Distribution sparkline in `g c`.** Beside the highlighted column's distinct count, the column-structure popup now draws a **12-cell block sparkline** of the sampled values — a numeric histogram for a numeric column, a value-length histogram otherwise — computed **in place from the already-loaded page (zero queries)**. It hides below 56 terminal columns so a phone keeps the plain counts, and the popup grows a little wider on a big terminal so the counts and the sparkline both fit.
- **Sidebar table info card (`i`).** Put the tree cursor on a table node and press `i` for a compact card: type, engine, comment, column / index counts, row estimate, data size and created time. Every field is read from **metadata already cached this session** — the tree's own table list, the open table's column metadata, and the per-database row / size estimates you got with `s` on a database row — so opening the card **never issues a query**. A table you have not opened yet degrades gracefully: the fields only an open would fill say *available after opening the table* and the card notes the table was never opened. `Esc` / `q` / `i` / `Enter` close it.
- **`Esc` now tells you what it did.** Closing an overlay or clearing a result filter flashes a short bilingual message in the status bar — `closed column structure` / `cleared result search` / `back to the sidebar` — that fades itself after **1.5 s**, so a keystroke is never silent and the status line never keeps stale text. The rules are uniform: an overlay's `Esc` closes **only the top layer** (a nested cell popup returns to the row popup first), the result set's `Esc` clears the search / filter highlight, and the editor's find `Esc` keeps the highlight until the next edit.
- **Readable big numbers (`#`).** In the results pane `#` cycles the display of large numeric cells through **raw → thousands** (`1234567` → `1,234,567`) **→ abbreviated** (`1.2M` / `3.4G`, base-1000), with the current mode flashed in the status bar. Only columns the **driver reports as numeric** are touched, and only once the integer part reaches six digits; a float gets separators in its integer part only (`1234567.89` → `1,234,567.89`), while a digit string in a `VARCHAR` or scientific notation is left alone. It is a **pure display layer**: `Y` (copy) and `e` (edit) always see the raw value the driver returned. Off by default (numbers show exactly as sent); press `#` to enable, and the mode persists to `~/.config/dbxt/tui.json` and is restored on the next launch.
- **Alternate-row zebra stripes (`%`).** Odd result rows are dimmed with the terminal's own *dim* attribute — legible but never harsh on a light or dark theme — while the cursor row and a row-select block override it, so the active row is never dimmed. Off by default (no banding, no chance of clashing with the selected-row highlight); `%` toggles it and stores the choice (`stripe`) in `tui.json`. Pure rendering, zero queries.
- **Jump to the statement that failed (`F8` / `Shift-F8`, `Alt-E`).** After a multi-statement run, the statements that failed get a red block in the editor (the one you are on is the brighter accent) and the caret lands on the first one. The status line keeps its error text and appends the failing ordinal (e.g. `· statement 2`); `F8` / `Shift-F8` step forward / backward through several failures (wrapping), and `Alt-E` does the same from the results pane. The line number is read out of the driver's own message when it reports one — MySQL `at line N`, PostgreSQL `LINE N:` — and everything is **pure text location, never a query**. `F8` is free in every pane; `Alt-E` only intercepts while an error is located, otherwise it stays the connection-export key. Any edit clears the highlight.
- **UNIX-timestamp preview in the cell popup (`v`).** When an integer cell of a numeric column falls in the epoch-seconds range (`1e9`..`4e10`), the `v` popup appends one gray line with the **local** time and a relative label — `🕒 2024-06-01 12:34:56 · 3 days ago`. It is a **read-only preview**: the value, and everything `y`/`Y` copies, is untouched, and no timezone semantics are guessed (a `VARCHAR` holding the same digits is left alone).

- **Global keys, one glance away.** Every context's footer now reserves a small **global segment** (shown on wide terminals, ≥ 100 columns) listing the global gestures that context reaches for most — the editor gets `Ctrl-O` snippets / `Ctrl-P` EXPLAIN / `Ctrl-S` commit, the results pane and sidebar get `Ctrl-L` mode-switch / `Ctrl-A` auto-collapse / `Tab`, and the `?` mini card ends with a fixed `Ctrl-L mode · [ ] tabs · F1 all` anchor. The full help's `— Global —` section is now a **complete ledger** of the router's global keys (including the batch queue's `Ctrl-T` / `Ctrl-S` / `Ctrl-X` and `Ctrl-D`). In **row-select mode** `Ctrl-A` selects every row on the page (the Redis / Mongo `a` equivalent), and in the **row-detail popup** `J` expands a JSON object/array field in place under its `(J pretty)` marker — `y`/`Y` always copy the raw value. All client-side, zero queries.
- **Pin a reference row (`g s`).** With a wide grid scrolled away from its header, `g s` marks the focused row as a **reference**: a light `❮` appears at its end and the status bar shows the current row's signed offset from it — `Δ+37`, plus the **first differing column** name (`Δ+37 (user_id)`) computed client-side from the loaded page. Press `g s` again to clear; only one reference row exists. Switching tables or re-running a query clears it automatically, and paging past the row simply hides the marker (never a query).
- **Freeze the current column (`g f`).** `g f` pins the focused column to the left edge so it stays visible while the grid scrolls sideways — the wide-table gesture `z` started (which only ever pins column 0). Up to **two** columns are frozen in total (counting `z`'s first column); pressing `g f` on a frozen column unfreezes it, and a frozen column's width still adjusts with `<` / `>`. In the MongoDB document grid `g f` keeps its R82 field-jump meaning (`g s` still pins the reference row there).
- **Data dictionary export (`g c` → `y`, `E`).** `y` inside the `g c` column popup copies the open table's structure as Markdown — a `## schema.table` heading, a column table (`column / type / key / nullable / default / comment`; the comment column is dropped entirely when no column has one) plus an index list and a foreign-key list, each emitted only when the backend reports rows. Everything comes from the cached `TableMeta` (**zero queries**). On the connection tree `E` walks the current database's tables and builds one `{db}-dictionary.md` document (first section: table count / dialect / generated-at), then offers the `Ctrl-Y` destination prompt (the default filename is prefilled; blank copies to the clipboard). A database with more than 200 cached tables asks through the red confirmation first, `Esc` during generation soft-cancels and discards the partial document, and read-only connections are welcome — the whole walk is a read.
- **Table / column comment view + edit (`c`, `n` in `g c`).** The structure view (`g d`) shows the open table's comment in its header (`—` when none; read best-effort via `get_table_comment_core` when the view opens, a failure stays silent). Press `c` for an input prefilled with the current comment; Enter generates the write SQL and routes it through the red write-confirmation pipeline (**never run silently**): `COMMENT ON TABLE … IS '…'` on PostgreSQL / the generic form, `ALTER TABLE … COMMENT = '…'` on MySQL. A blank value clears it (`IS NULL` on PostgreSQL, `''` on MySQL). Inside the `g c` column popup, `n` edits the highlighted column's comment through the same pipeline (`COMMENT ON COLUMN` on PostgreSQL / the generic form); MySQL column comments are read-only with a note, and SQLite has no comments so the action is hidden. After a successful write the comment cache is invalidated and the structure view re-reads its metadata. Read-only connections hide the write actions.

## Features

**Connections** — shared with DBX Desktop
- Connections live in DBX's own SQLite store (`dbx.db`), so everything you configured there shows up automatically.
- `c` creates a connection in-TUI, `e` edits the highlighted one (prefilled, including its SSH tunnel), `p` duplicates one into the form, `x` deletes one behind a red confirmation, `Enter` connects; rows are colour-coded by database family.
- The connection form has a `color` row: `Space` cycles a preset palette (none → 10 colours → custom), `Enter` types a free-form `#RRGGBB`, and a live swatch previews the result. The colour is stored in DBX's own `color` field, so it round-trips with the desktop app, survives editing and duplication, and tints the sidebar, picker, title bar, status line and the `d` switcher header (the name stays fully readable — colour is only an accent).
- **Fast entry.** The form's fields follow the real creation flow — `db_type` → `name` → `host` → `port` → `user` → `password` → `database` → `query_timeout` — so `Tab` walks them in the order you fill them. Picking a `db_type` **fills its default port** (MySQL `3306` / PostgreSQL `5432` / Redis `6379` / MongoDB `27017`); the moment you type a port yourself it is pinned and a later type change never overwrites it. Leave `name` blank and it is **generated on save as `host-db_type`** (e.g. `localhost-postgres`), so you never have to name a throwaway connection by hand.
- **Per-connection query timeout.** The `query_timeout` row takes a number of seconds — blank keeps the kernel default (60 s), `0` means **no limit**, and any other value bounds the query. It is stored in DBX's own `ConnectionConfig::query_timeout_secs` (so the desktop app sees the same value) and passed to every editor / table-browse query via the kernel's timeout channel; on **PostgreSQL** it is also mirrored into a connection-level `options=-c statement_timeout=…`, so the server enforces it on every pooled session and `SHOW statement_timeout` reflects it — **no per-query `SET`**. When a query hits the limit dbxt rewrites the raw driver error into `Query timed out (30s) — raise the timeout or optimize the statement` instead of leaking a driver message.
- `s` in the picker cycles the sort order: **name** (default) → **type** → **colour**, so all your production (red) connections line up together.
- `d` opens a switcher — MySQL databases, PostgreSQL (and other schema-aware engines') **schemas then databases**, MongoDB databases and Redis logical DBs, all one gesture.
- `o` returns to the picker; `r` reloads the list in place.
- **Open a SQLite file directly (`L`).** Press `L` in the picker (or any browse pane) to pick a `.db` / `.sqlite` / `.sqlite3` file from the current directory: type a path, `↑`/`↓` to walk the listing, `Tab` to complete, `Enter` to open; sub-directories descend in place. The last five files stay at the top (Enter reconnects, `Del` forgets). The connection is **session-only** — it never touches the saved connection store, so a restart shows no ghost.
- **Connection status dots + manual disconnect.** Each connection root in the sidebar (and the Redis header) carries a status dot whose **shape** tells the state apart — `●` live (a pool exists, the connection is queryable), `○` disconnected, `◐` connecting — while the dot keeps the connection's own colour (identity), so the states stay readable with any colour vision. A disconnected root's name is dimmed, and its cached databases / tables stay visible but muted; expanding it (or clicking one of its databases) reconnects lazily. `x` on a connection root opens a red **Disconnect** confirmation (`Disconnect conn-x?` — uncommitted manual transactions roll back); the pools are drained through the kernel's own user-disconnect path (`remove_connection_pools`, which rolls back manual-transaction sessions first — never a bare drain). Disconnecting the *active* connection collapses it to a grey root and moves the cursor to the nearest other root — the sidebar keeps its tree and the picker never flashes an empty screen. In the connection picker `d` disconnects the highlighted connection, which is also the path for Redis (whose browser has no tree root row); MongoDB disconnects through the same `x` on its root. The saved config is never touched — only the pools.

**Safety valves** — for the times you keep a production connection open
- **Read-only connections.** The form has a `read_only` row (`Space` / `Enter` toggles it). Once on, that connection **refuses every write statement** — `INSERT` / `UPDATE` / `DELETE` / DDL — with a red `✗ read-only connection: write statement refused (INSERT)` status, while `SELECT` / `SHOW` / `EXPLAIN` / `DESCRIBE` / `VALUES` / `TABLE` run as usual. The check is **statement-level and purely textual** (no extra query): the first keyword decides, `WITH …` is reduced to its top-level verb and `EXPLAIN` unwrapped (so `EXPLAIN ANALYZE DELETE` is still a write), and anything ambiguous — an unrecognised keyword, a bare `BEGIN`, a session `SET` — is treated as a write (fail closed). A mixed batch (`SELECT 1; INSERT …`) is refused as a whole. Every write path is covered by one choke point (editor, `.sql` file script, history direct run, row edit / insert / delete, batch commit, red-confirm accept) plus the non-SQL writers (CSV import, a read-only *target* in the `Alt-T` transfer wizard, Redis / MongoDB writes), and the sidebar tree prefixes the root with `🔒` (in the connection colour). The flag is stored in DBX's own `ConnectionConfig::read_only`, so it round-trips with the desktop app. **`!`** on the tree (or the Redis key browser) flips the connection under the cursor — else the active one — behind the same red confirmation layer: the root's `🔒` and the editor badge appear / disappear at once, and the toggle is persisted through the same single-row store upsert, so it survives a restart.
- **Two-stage quit.** When the editor holds SQL that has not been executed (or a sidebar / result filter is active), the first `q` (or `Ctrl-C`) only warns — `Unrun editor SQL · press q / Ctrl-C again to quit · Esc to stay` — and a second press quits; `Esc` (or any other key) stays. A clean editor quits on the first press, exactly as before.
- **Dangerous-statement impact.** The red confirmation layer now echoes the `WHERE` predicate of every `UPDATE` / `DELETE` in the statement(s), truncated to 80 columns (`WHERE predicate: id = 4821`), so a bounded-looking write is judged on the predicate it will really run. `TRUNCATE` and `ALTER … DROP COLUMN` / `DROP CONSTRAINT` join `DROP` and unbounded `UPDATE` / `DELETE` in the danger list. A `SELECT` with `LIMIT > 10000` is **not blocked** — it just lands with a yellow `⚠ Large result set · LIMIT 20000 · may be slow` heads-up.

**Quick lookups & comparison**
- **Desktop sidebar groups.** If you grouped connections in DBX Desktop, the sidebar mirrors that tree: a group draws as a foldable `▾ 生产 [2]` node (the badge counts the live connections inside, nested groups included), its connections are nested in the desktop's own order, and nested groups are indented a level further. `h` / `l` (or `←` / `→`) fold and unfold a group with the same vim-tree rule as every other node, and the fold state is written to `tui.json` and remembered across sessions; `x` on a group row is a no-op (a group has no connection pool) and no longer leaks into the type-to-filter. the R47b status dot / `🔒` / colour still apply to each connection root. Groups with no live connection (or none matching the active table filter) are hidden, and the filter keeps a group as soon as one of its connections matches. A store with no `sidebar_layout` — or a corrupt one — simply lists every connection flat, exactly as before. The layout is read once per session (a desktop regrouping shows up the next time dbxt opens the connection store) through the same kernel store call DBX itself uses.
- **Column-structure popup (`g c`).** In the results pane, `g c` overlays a compact, scrollable list of the open table's columns — name, type, key (`PRI` / `UNI` / `MUL`), default, `NOT NULL`, comment — from the metadata already cached when the table was loaded (**no extra query**). `/` filters the list by column name as you type, `j` / `k` / `PgUp` / `PgDn` move the highlight, `Enter` jumps to that column (the grid's cell cursor lands there and the popup closes; a hidden column reports instead), `Esc` / `q` closes. The highlighted column also shows its **value distribution** in place — non-null / null / distinct counts, a **12-cell block sparkline** of the sampled values (numeric histogram for a numeric column, value-length histogram otherwise; hidden below 56 columns), and for a numeric column `min` / `max` / `avg` — computed client-side from the loaded page (never a query); no data loaded shows a hint, and a page over 5,000 rows is sampled with a `(stats over the first N rows)` note. This is the quick check while writing SQL without leaving the grid for the full `g d` structure view; a query result (no table metadata) falls back to the grid's column names.
- **Pin the results pane (`Alt-F`).** `Alt-F` in the results pane snapshots the current grid into a strip above the live one, marked `📌`. Switch to another table (or database) and the pinned grid stays on top while the new data loads underneath — an up/down comparison straight from the terminal. `Alt-F` again releases it; a switch to another connection or backend clears it. `Alt-F` stays the SQL formatter in the editor, so the two never collide.
- **Context-scoped completion.** `Alt-/` already completed tables, columns and keywords; the candidate list is now strict about context — after `FROM` / `JOIN` / `INTO` it offers **only tables**, after `WHERE` / `ON` / `SET` / `SELECT` (and after `(`) **only columns** — all from the connection's cached metadata, never a round trip. The popup is one column and caps at **5 candidates below 40 terminal columns** (8 otherwise), so it never buries the SQL being typed on a phone.

**Connection import, export & migration (`Alt-E` / `Alt-I`)**
- `Alt-E` exports **every** saved connection as a self-describing JSON bundle (`format` / `version` / `connections[]`, default `~/dbxt-connections.json`). Passwords are **excluded by default**; `p` enables them behind a red plaintext-warning confirmation, and `y` copies the JSON to the clipboard instead of writing a file. The status line reports the destination and the count.
- `Alt-I` imports connections from a path; the format is auto-detected — the dbxt bundle, a DBeaver `data-sources.json` (the standard `~/.local/share/DBeaverData/workspace6/General/.dbeaver/data-sources.json`), or a Navicat `.ncx` XML export. A preview lists every connection (name / engine / host / SSH / colour / `needs password`), flags same-name collisions, and lists drivers that could not be mapped (skipped).
- Duplicate names are resolved per row or in bulk: `s` skip, `r` overwrite (matched by name, behind a red confirmation because the existing config is deleted first), `b` keep both (`name-imported`); `Space` toggles a row, `d` cycles its policy, `Enter` imports. Every write goes through `LocalBackend`, so imported connections are immediately usable (connect and verify as usual).
- **DBeaver** provider / driver ids map to dbxt engines (`mysql8`→`mysql`, `postgresql`→`postgres`, `mariadb`, `duckdb`, `mongodb`, `sqlserver`, …) and the `ssh-tunnel` block becomes a real SSH layer. **Navicat** `.ncx` XML is parsed with a tolerant hand-written scanner (child elements or attributes). Passwords in both stores are encrypted with keys dbxt does not have, so they are never read — imported rows are marked `needs password` and the completion status counts them.

**SSH tunnels (jump hosts)**
- A tunneled connection configured in DBX Desktop works in dbxt unchanged: dbxt passes `transport_layers` straight through to the kernel, so no re-entry is needed.
- The connection form has an `ssh_tunnel` section: `ssh_host` / `ssh_port` (22) / `ssh_user`, and an `ssh_auth` login method of `password`, `key` (key path + passphrase) or `agent` (SSH agent, optional socket path).
- `ssh_host` also accepts a `~/.ssh/config` **alias**; the kernel resolves it, including `ProxyJump` (which expands into a multi-hop chain).
- The tunnel forwards to the connection's own `host:port`; the form shows that target as `远端目标` / `remote target`. To forward somewhere else, change the connection's `host`/`port`.
- The first connection to an unknown jump host shows a host-key fingerprint dialog (`y`/`Enter` accept & remember, `s` trust for this session only, `n`/`Esc` reject). Accepted keys go to DBX's own `<store-dir>/known_hosts`; `~/.ssh/known_hosts` is read but never written.
- Tunnel failures are reported by stage: **SSH authentication failed**, **SSH host unreachable**, or **tunnel up but remote database unreachable** — so a wrong password, a wrong bastion address and a closed far-side port are told apart.

**SQL editor & results**
- Multi-line editor with shell-style `↑`/`↓` history (seeded from DBX's shared query history); a selection always runs on its own (`F5` or `Ctrl-J`), otherwise `F5` runs the whole editor and `Ctrl-J` runs the statement under the cursor. Every run is written back into that shared history (connection, database, timing, success flag), so the recall list and the `Alt-H` panel also cover the statements you ran here.
- `Alt-/` completes identifiers from context (tables / columns / keywords, tagged `T`/`C`/`K`); `Tab` accepts. (`Ctrl-Space` still works as a compatibility alias, but it clashes with input-method switching, so it is no longer advertised.)
- `Alt-H` opens the **query-history panel** (latest 300 statements, newest first): repeated statements are **merged into one row with a count (`×n`)** so a re-run loop cannot flood the list — the newest occurrence's time / duration are what the row shows. Each row shows the time, the statement's first line, its execution time (`12ms` / `1.2s`) when dbxt recorded one, a run-origin badge (`编` editor / `脚` script / `直` direct) and the source connection. `f`avourites are pinned in a **收藏** section above the chronological list (and move live as you toggle `f`). `↑`/`↓`/`PgUp`/`PgDn` move, `Enter` recalls the statement into the editor (cursor at the end), **`Ctrl-Enter` / `p` runs it straight away** through the normal pipeline (multi-statement included; the panel closes and the result lands in the results pane with an elapsed-time status — no editor round trip), `f` favourites / unfavourites it in DBX's `saved_sql_files`, `y` / `Y` copies the whole statement, `Del` deletes one entry behind a red confirmation (history only — never database data), and `/` filters by statement text **or source connection or origin badge** (case-insensitive substring; Enter keeps the filter, Esc clears it). The focused statement is previewed, wrapped, below the list. **This session's own runs float to the top**, marked with a cyan `●`: dbxt keeps an in-memory log of the last 20 statements it actually sent to the server (LRU, repeats deduped and floated up, across panes and connections), so the panel shows something the instant it opens — before the persisted store answers — with **zero queries** and nothing written to disk. Those are trimmed to statement text and never touch the store, so `Del` declines them (they clear when dbxt exits) while `Enter` recall, `Ctrl-Enter` direct run and `y` / `Y` copy work as usual.
- `Alt-F` formats the editor's SQL — keywords upper-cased, main clauses on their own line, `JOIN` on its own line, two-space indent, whitespace collapsed — while leaving string literals, quoted identifiers, comments and function names (`count(`) untouched. Pressing it again compresses a formatted statement back to one line (idempotent toggle); `Ctrl-Z` / `Ctrl-U` undoes it in one step and `Ctrl-Y` / `Ctrl-R` redoes it.
- The editor keeps a vim/readline feel: `%` jumps to the matching bracket when the cursor is on or just after a `()[]{}` bracket (anywhere else `%` is typed literally, so `LIKE '%x%'` is never hijacked; brackets inside strings and comments are ignored), `Ctrl-A`/`Ctrl-E` go to the line head/tail (`Home`/`End` too), `Ctrl-K` / `Ctrl-Shift-K` kill to the end of the line and `Ctrl-W` deletes the previous word.
- **Enter auto-indent & bracket auto-pair (on by default).** `Enter` after a line that ends with `SELECT` / `FROM` / `WHERE` / `AND` / `OR` / `JOIN` / `ON` / `SET` / `VALUES` or `(` `[` `{` `,` — or that has an unclosed bracket — starts the new line at the previous indent **plus two spaces**; a blank line inherits nothing and any other line simply passes its indent down. Typing `(` or `[` inserts the matching `)` / `]` and leaves the caret between them; when the caret already sits on the same closer, `)` / `]` steps over it instead of typing a duplicate. Both are pure, client-side edit behaviour — **no query, no display change** — and both respect the SQL lexer, so a bracket or keyword inside a string literal, quoted identifier or comment is never treated as code. Each has its own switch in `~/.config/dbxt/tui.json` (`editor_indent` / `editor_pairs`, both default `true`; a `false` there turns just that one off).
- **Statement gutter (`F2`, off by default).** With it on, the editor reserves a narrow left gutter and prints `1.` `2.` … on each statement's first line (the same semicolon splitter `Ctrl-J` / `Alt-↓` use), so a long script reads as numbered blocks. It is **render-only — the SQL text itself is never touched** — and the choice persists as `stmt_gutter` in `~/.config/dbxt/tui.json`. A buffer above 256 KiB keeps the gutter off for that frame (never a lexer per frame).
- **Find in the editor (`Ctrl-F`).** The bottom bar takes a search term and highlights every match in the buffer as you type — **case-insensitive substring, client-side only** (no statement is ever sent). `Enter` / `F3` / `Alt-N` jump to the next match, `Alt-B` (`Shift-Enter` / `Shift-F3` where the terminal reports them) to the previous, both wrapping; the status bar shows the current position as `3/7`. `Esc` closes the input but keeps the highlight so the matches stay readable, `F3` / `Alt-N` keep cycling, and the next edit clears it. The current match is drawn in the accent colour and the rest in a plain marker, tabs / wide CJK characters included. `Ctrl-F` stays the results pane's page-turn key; the editor owns it only while it has focus.
- **Comment toggle & editor clipboard ring.** `Ctrl-/` toggles `-- ` line comments across the selection, or just the line under the caret when nothing is selected — indentation is preserved, a multi-line selection is handled one line at a time (never a `/* */` block), and a line that is already a real comment loses exactly one `--` (plus one following space). A `--` that continues a multi-line string literal is invisible to the decision: the shared SQL lexer draws the boundary, so a quote-hidden `--` is never mistaken for a comment. A block stays selected after the toggle, so a second press flips it back. Terminals disagree on what `Ctrl-/` sends (the extended keyboard protocol reports `/`; a legacy terminal sends `0x1F`, which crossterm spells `Ctrl-_` or `Ctrl-7`), so all three are accepted; in the editor `Alt-C` is the documented fallback (elsewhere it still toggles compact columns). Separate from that, `Ctrl-Shift-V` pastes from an in-memory **clipboard ring** of the last five editor copy / cut payloads, replacing the selection (or inserting at the caret) and keeping the paste selected so repeated presses cycle through the ring; `Ctrl-C` / `Ctrl-X` with a live selection copy / cut into it (with no selection they keep their old jobs — quit / clear the batch queue). The ring is session-only, never written to disk, and never touches the `Y` / OSC 52 system-clipboard channel.
- **Row-detail field locate & numeric snapshot.** Inside the row-detail popup (`Enter`/`o`), `\` locates a field by **column name or value** — every match gets a quiet `›` mark at the line head and `n`/`N` cycle them, while `Esc` clears the marks (a second `Esc` closes the popup). The fields themselves are never hidden: `\` is the *locating* twin of `/`, which stays the narrowing filter, and the two swap cleanly (opening one clears the other). On the results grid, `S` toggles a **numeric snapshot** in the status bar: with a numeric column focused it shows `min 12 · max 98 · avg 45.3` over the loaded window, recomputed as the column cursor moves. NULL, blanks and thousands-separated text (`1,234`) are skipped / parsed, and a column with no numeric value shows nothing. `S` is the uppercase twin of `s` (sort), the snapshot is **off by default** and session-only — it changes persistent status-bar content, a visual change — and every part of both gestures is pure client-side with zero queries.
- `Alt-G` opens **global search**: it scans the `char` / `varchar` / `text` columns of every table on the current database (and PostgreSQL schema) for a term, case-insensitively, and lists each hit as `table.column → value` with the match highlighted. One bounded `SELECT … LIMIT` runs per table (`DBXT_SEARCH_SCAN_LIMIT`, default 1000), and a table estimated above `DBXT_SEARCH_MAX_ROWS` (default 1,000,000) is skipped and reported. `↑`/`↓` move, `Enter` jumps to the table and lands on the matching row, `y` copies the matched value, `r` re-runs, and `Esc` aborts a running scan (keeping partial results). MySQL / PostgreSQL only.
- `Alt-L` loads and runs a **`.sql` file**: type a path (a leading `~` expands), then confirm a preview showing the file size, statement count and target connection/database, with the script wrapped below. A file over 2 MB warns, and one containing `DROP`, `TRUNCATE`, or an `UPDATE`/`DELETE` without `WHERE` routes through the same red confirmation layer before anything runs. The whole file is one history entry, and the result is the usual per-statement script summary with error messages inline; `e` loads the file into the editor instead.
- Every run keeps its own result tab (`[` / `]`); execution time and affected rows are shown. A **tab strip** sits above the results grid, labelling each tab `number:first 12 chars of the statement` with the active tab highlighted; on a narrow terminal the middle tabs fold to `…` while the active one stays visible. `Alt-W` closes the active result tab (the last one is kept; a tab with an unconfirmed edit is left alone; client-side only, never queries).
- `Ctrl-P` runs `EXPLAIN`, `Ctrl-Y` exports the result set (CSV / JSON / NDJSON / Markdown / INSERT), `Ctrl-N` loads more when a result hit the row cap.
- `Ctrl-O` inserts a DBX saved snippet; `s` saves the editor's SQL back into that shared store, `Alt-S` does the same in one step from the editor, `/` filters the list by name / SQL text, `d` deletes a favourite behind a red confirmation, and the list caps at **100** per connection (a save past it is refused with a hint to delete first).
- Multi-statement scripts (`a; b; c;`) run as a batch, one row per statement; while it runs the status bar counts statements (`3/7`) and the summary names the total elapsed time; `Enter` drills into one.

**Table data & editing**
- `Enter` on a table runs a paginated `SELECT *`; `↑`/`↓` walk rows continuously across page edges, `n`/`p` turn pages keeping the relative row. Each page load refreshes the status bar in place with the absolute row window (`Loading big page 3… (rows 101-150)`), so a deep page reads as the batch it is.
- The sidebar table list filters as you type — any printable key starts a case-insensitive substring filter at once (`/` opens an empty one), `Enter` jumps to the first match and **acts** on it (a matched connection / database switches, a table opens) with a bilingual status hint on a miss, `Ctrl-U` / `Alt-Backspace` clears it, and a first-letter jump (`Alt`+letter, then `;`/`,` to cycle forward/back) skips through a long list without scanning; `s` cycles the order by name / type (on a database row `s` instead fetches that database's size — see below).
- The sidebar is a **connection tree**: `connection → database → table`, indented two levels (DBeaver style). `h`/`l` (or `←`/`→`) collapse / expand with **vim-tree semantics**: a first press folds an expanded node in place, a second climbs to its parent, and `l` opens a collapsed node then steps into its first child — groups, connections, databases and tables all answer the same way. The tree cursor paints its **whole row** out to the sidebar's right edge, so the selected row reads as one solid band. `Enter` opens (connection = switch and expand, database = switch to it, table = browse data), and collapse state is remembered for the session (groups persist to `tui.json`). Expanding a non-active connection **lazily connects** and lists its databases asynchronously (a failure shows an error row without breaking the tree); `j`/`k` walk the whole tree (count prefix `3j`). A filter keeps a node when it or a descendant matches, so database / connection ancestors of a table hit stay visible; `[`/`]` cycle databases. **`s` on a database row** lazily fetches its aggregate size (`2.1 GB`; `information_schema` `SUM(data_length+index_length)` on MySQL, `pg_database_size` on PostgreSQL) and the row estimate of every table in the current database (`table_rows` / `reltuples`) — cached for the session, right-aligned and muted, auto-hidden below 56 columns, and never scanned on startup or automatically. **`Y`** on a connection row copies that connection in one step (no form) as `xxx-copy`, keeping its password and SSH tunnel, and the new root appears in the tree immediately. Each root also carries the R47b **status dot** (`●` live / `○` disconnected / `◐` connecting, in the connection colour) and `x` disconnects it (see Connections above). `r` on a connection root or a group row renames it **in place** (`Enter` saves, `Esc` cancels); `Shift`+`↑`/`↓` moves it one slot up / down within its level and writes the order back into the desktop group layout (a top-level ungrouped connection follows the picker's name sort instead).
- Continuous paging prefers **keyset** reads when the table has a primary key: the next page is `WHERE pk > last ORDER BY pk LIMIT n` and the previous page seeks backwards, so the cost no longer grows with the page number (an early page and page 20,000 of a ten-million-row table both run in milliseconds). A jump that is not exactly one page, a table with no primary key, or a sort on a non-key column keeps the classic `LIMIT … OFFSET` path. With no explicit sort the browser orders by the primary key, which makes page boundaries deterministic (a table without a primary key keeps the engine's natural order).
- Row counts are cached per `db.schema.table` + filter for the session. On a large table the first load samples at most `DBXT_COUNT_SAMPLE_LIMIT` rows (default 500,000) and shows `>500000 行` instead of paying a full `COUNT(*)` scan on every page; set `DBXT_COUNT_SAMPLE_LIMIT=0` to always count exactly. A small table still shows its exact total.
- `←`/`→` move a cell cursor, `}`/`{` jump to the next / previous row whose focused-column cell is non-blank (skipping `NULL` / empty), `Home`/`End` (and `gg`/`G`) jump to the **first / last row** and park the cell cursor back on the first column, `z` pins the first data column, `Enter` (or `o`) opens the **whole row** as a vertical `column = value` list — the row popup is the primary way to read one row, and its title carries the primary key (`row 12 · id=4821`). Inside it `↑`/`↓`/`j`/`k` or `n`/`p` (with a vim count, `5j`) move the selected column, `/` filters by column name **or value** (for 40+ column tables), `y`/`Y` copy the selected value (the status names the column), and `Enter`/`v` drill into the full cell popup (below 56 columns each field stacks as `field:` above its indented value); `Esc` unwinds cell → row → grid. `v` from the grid opens the cell popup directly, and a bottom bar shows horizontal position (the thin dashed scroll bar only appears for ~2.5 s after a horizontal scroll — wheel, swipe, `◀`/`▶` or a column jump — and auto-hides at rest so the border stays a plain line). A **long value (>40 characters) is abbreviated in the grid** to its first 38 columns plus `…` so one wide column cannot crowd out its neighbours; `v` / the row popup still show the **full** value, and a real `NULL` keeps its grey italic `NULL` (never `∅`).
- **Pretty JSON cells.** When `v` opens a cell whose value is a JSON **object or array** — PostgreSQL `json`/`jsonb`, a nested MongoDB document field, a Redis hash value holding JSON — it is re-indented automatically: **indentation and line breaks only**. `J` toggles between the pretty and raw views (a non-JSON cell says so), and `y`/`Y` always copy the **original** value, never the indented form. A scalar (`42`, `"x"`, `true`) or non-JSON text stays verbatim, so `v` never reformats something it does not understand. Values that carry `\uXXXX` escapes also get a grey **decoded** line at the bottom, and `U` cycles the body through **raw → escape-decoded → whole-value re-escape** (all non-ASCII as `\uXXXX`; a pure-ASCII value has only the raw / decoded two states) — a failed decode (e.g. a lone surrogate) reports an error without changing anything, and `y`/`Y` still copy the raw value.
- `e` edits the focused cell in a diff layer showing old → new, the `WHERE` clause, the primary key and the full `UPDATE`.
- `i` inserts from a column template and `Delete` / `Ctrl-D` deletes with a bound `WHERE` — every write is confirmed first.
- `Ctrl-T` queues writes and `Ctrl-S` runs them as one `BEGIN … COMMIT`; `f` filters, `s` sorts, `Ctrl-K` adds a sort key, `Ctrl-R` clears.
- `y` copies the focused row as `INSERT INTO … VALUES (…)`; `/` searches the visible rows (hiding non-matches), `\` finds a term in **any** cell of the loaded page (highlights every match, `Enter`/`n`/`Shift-N` cycle, `Esc` clears; never hides a row), while `gv` locates a value in the sort / primary-key column without hiding anything (`n`/`N` cycle the hits); `|` jumps the cell cursor to a column by number or name prefix on a wide table.
- `V` enters **row-select mode** on the result grid: `↑`/`↓` move the anchor, `Shift`+`↑`/`↓` (or `v`/`V`) stretch the block, `Ctrl-A` selects every row on the page, `Ctrl-U` sets one column to one value (see below), `Esc` leaves; the selected rows paint as a solid reverse-video band. `Y` copies the block as TSV (with a header line), `d` generates a `DELETE … WHERE pk IN (…)` (or a composite-key `OR` chain) and `c` an `UPDATE … SET … WHERE pk = …` template — both land in the editor for review and are **never executed** (the zero-write rule); a result without a primary key (expressions, aggregates, keyless tables) is refused with a `no primary key` note.
- **Batch set-value (`Ctrl-U` in row-select mode).** With a row block selected, `Ctrl-U` opens a one-line value prompt for the **focused column**: type a new value and the generated `UPDATE table SET col = <value> WHERE pk IN (…)` previews live (one statement for the whole block, a composite key falls back to a portable `(k1 = … AND k2 = …) OR (…)` chain). The value is wrapped for the column's **declared type** — a numeric column emits a bare literal, a text column is quoted with `'` doubled, and a blank box (or the word `NULL`) is SQL `NULL`; wrap a value in `'…'` to force a string. `Enter` hands the statement to the red **confirmation layer**, which shows the **affected row count** on both language tracks, and only confirming it runs (a read-only connection is refused before the prompt). The typed value is remembered per table column — the prompt's `↑`/`↓` recall the last three templates (`Del` clears the highlighted one, or the whole column's memory, into `tui.json`) — and the executed statement joins the `Alt-H` history. A single statement names at most **200** rows: a larger block is truncated to the first 200 and the statement and confirmation both carry a truncation warning.

**Table structure**
- `r` shows fields (type / key / nullable / default / comment); `t` toggles the dialect-aware `SHOW CREATE TABLE` DDL.
- `Alt-D` **diffs two table structures**: the focused table is the source, then pick a target table (or `c` to pick *another connection* and diff across databases / dialects). The overlay shows, for every column, `+` (missing in the target — add), `-` (extra in the target — drop) and `~` (attributes differ: type / nullable / default / comment / charset / collation / extra / PK / unique), plus a second tab for indexes (name, columns, unique, filter) and a `⚠ cross-dialect` badge when the two sides use different engines. Type comparison is dialect-aware: within one engine it ignores cosmetic display width (`int(11)` = `int`), and across engines it maps the common types (`varchar(255)` ≈ `character varying(255)`, `int` ≈ `integer`, `tinyint(1)` ≈ `smallint`, `jsonb` ≈ `json`, …); a type outside the map is shown with `?` and both raw spellings.
- `y` copies a plain-text diff summary (paste it into a ticket), `g` generates the `ALTER` script that would rewrite the **target** to match the source (`ADD` / `DROP` / `MODIFY`, indexes included, plus `COMMENT ON COLUMN` for PostgreSQL) — dbxt **never executes it**: it is shown only in a preview tab so you can copy it into another client or the editor.
- `Shift+Alt-D` compares two **databases' table lists** (only-source / only-target / shared); `Enter` on a shared table opens its table diff. The generated `ALTER` is dialect-quoted (MySQL backticks, PostgreSQL `"double quotes"`).
- `Alt-K` **compares two tables' data** — the schema diff's row-level sibling (everywhere the picker is open, `m` toggles schema ↔ data). Pick a target table (or `c` for another connection, so MySQL ↔ PostgreSQL works) and optionally type a `WHERE` (`w`) that both sides share. When both tables have a primary key it is the alignment key and only the name-intersection columns are compared, so column order does not matter; when **neither** side has a primary key the compare falls back to **row-order alignment** over the first 500 rows of each (keyed `#1`, `#2`, …), and the sync-SQL generator is disabled because there is no unique key to target. The primary-key compare streams 1000-row chunks in the background (a `COUNT(*)` forecasts the scale; `Esc` aborts and keeps what it has, and a result past 5,000 difference rows is capped with a note to narrow the scope). The overlay's summary shows the source / target row counts, the source-only `<` / target-only `>` / differing `≠` counts, and `compared N rows`; `Tab` switches to those lists, `n` / `p` (or `j` / `k`) step between difference rows, and `Enter` expands a `≠` row into a column-level side-by-side. Values compare as text, with the cross-dialect canonical mapping (`1` = `1.0`, `true` = `1`, `2026-01-01T…` = `2026-01-01 …`); an unmapped type keeps its raw spelling and is flagged `?`. `y` copies a plain-text summary, `Y` copies the difference rows as CSV (`mark,key,column,source,target`, RFC 4180 escaped), `Ctrl-E` writes that CSV to the temp dir as `dbxt-diff-<timestamp>.csv` and shows the path, and `g` generates the source→target sync script (`INSERT` / `UPDATE` / `DELETE`, values escaped for the target dialect) in a preview tab — dbxt **never executes it**.
- `Alt-T` **transfers a table's structure and/or rows** to another SQL connection (migration, backup, seeding a test database). A three-step wizard: ① pick the target connection (the current one by default, so MySQL → PostgreSQL works either way), ② edit the target database / schema / table name (defaults to the same name; renaming copies the table), ③ pick the mode — **create + copy** (default), **create only** (structure), or **insert into existing** (append) — and options. When the target table already exists dbxt stops with an error (never silently overwrites); `o` switches to **overwrite**, which routes through a red confirmation layer because it runs `DROP TABLE` first. Options: `w` a `WHERE` subset, `l` a `LIMIT` cap, `i` copy indexes, `a` carry the auto-increment (MySQL) / build a `serial` column (PostgreSQL), and `s` stop-on-error (reports the row) / skip-and-continue. The copy streams 1000-row keyset chunks from the source (falling back to `OFFSET` when there is no primary key) into 500-row transactional `INSERT` batches on the target, with types mapped through the same cross-dialect table the schema diff uses (including `bytea`/`blob`, array and quoted-literal escaping for the target dialect). A source estimated above 1,000,000 rows asks for one more `Enter` before it starts, a failed batch retries once, and the status line shows rows / chunks / rows-per-second. `Esc` aborts and **keeps every committed batch**, reporting the breakpoint primary key. The completion summary shows source rows / moved / skipped / time / rate / target, `g` copies it, and `b` jumps to the target table when it lives on the current connection. Redis / MongoDB are out of scope (document-model mapping is a separate problem).

**Import & export**
- `I` imports a CSV into the focused table (the browsed table, else the sidebar selection). Enter a path (a leading `~` expands to `$HOME`) and confirm the preview: encoding, delimiter, row count and file size, the first five parsed rows, and the column mapping with per-column type inference (`int` / `float` / `bool` / `date` / `datetime` / `text`).
- CSV headers match table columns by name (case-insensitive); a table column absent from the CSV keeps its default (usually `NULL`), and an extra CSV column blocks the import with a clear message.
- `m` toggles append / overwrite (overwrite clears the table first and turns the preview border red), `s` toggles stop-on-error (default, reports the failing row) / skip-and-continue (reports every skipped row). Rows are written in transactional batches of 500 with per-batch progress.
- Encoding is auto-detected — UTF-8, otherwise GB18030/GBK (the common Chinese encoding) — and the delimiter is sniffed from the header (`,` / `;` / TAB). Excel `.xlsx` is deliberately not supported.
- `Ctrl-Y` exports the focused result set as CSV, JSON (array), NDJSON, Markdown, `INSERT` (one statement per row) or batched `INSERT` (multi-row `VALUES`). Pick a format, then a destination: blank copies via OSC 52, a path writes a file. Results over 10,000 rows warn that generation may take a moment.

**Redis**
- Connecting to Redis opens a paginated `SCAN` key browser (never `KEYS *`) with type + TTL badges, a server-side `MATCH` pattern (`/`) and logical-DB switching.
- The key list shares the SQL sidebar's quick-locate feel: any printable character starts a **one-step substring filter** over the loaded keys (hits highlighted, `Enter` opens the first, `Esc` clears), `Alt`+letter does a **first-letter cycle jump** (`;`/`,` repeat it), `1-9` jumps to the Nth key and `3j`/`3k` repeat a move.
- `Enter` renders the value by type — string, hash, list, set, sorted set, stream, RedisJSON — with load-more for large collections; `y` copies the focused value and `Esc` returns to the list.
- On a narrow screen the type badge and TTL fuse into one token (`S·12s`) so a key row never wraps. On any width the TTL is shown compactly at the end of the row — `45s` / `5m` / `2h` / `3d`, with `-1` permanent and `-2` missing — rendered from the value the `SCAN` page already carried and counting down locally once a second.
- `e` / `x` / `m` / `Del` edit, set TTL, rename and delete; `Space` multi-selects and drives batch delete / TTL / prefix-rename behind the red confirmation layer.
- **`T` sets the focused key's TTL** straight from the list (no need to open the value first) through the same red layer: seconds by default, with an explicit `s` / `ms` / `m` / `h` / `d` suffix (`500ms` becomes `PEXPIRE`, `-1` persists, `0` deletes). The write is refused on a read-only connection, and on success the loaded row's TTL is updated **in place**, so the SCAN cursor and page position stay put.
- **`t` cycles a client-side type filter** over the loaded keys — all → string → hash → list → set → zset → stream — and **`Ctrl-T` orders the loaded keys by TTL** (scan order → ascending → descending). Both are pure local views of the already-loaded window (zero queries), and the active filter / order is echoed on the browser header row.
- The raw `redis-cli` console (`Ctrl-L`) remains for anything else.

**MongoDB**
- Connecting to MongoDB lists collections; `Enter` browses documents as a grid over the union of top-level keys (`_id` first). The collection list uses the same filter / first-letter-jump / direct-jump keys as the SQL table list.
- `n`/`p` page, `f` applies a JSON filter, `r` shows the collection's indexes; `y` copies the focused document as pretty JSON and `Esc` returns to the collection list.
- **`g f` jumps to the first loaded document that carries a field** — a bare name or a dotted nested path (`a.b.0`) — client-side over the already-loaded page, so no query is sent. Every row ends with a `size(B)` column holding the document's compact JSON byte length, and **`Ctrl-S` orders the loaded page by size** (natural order → largest first → smallest first, restoring the arrival order exactly) — a purely local view echoed on the grid header.
- **`c` extracts a dotted sub-path from the focused document** (`a.b.0.name`) and copies it through the shared clipboard channel; a path that does not exist reports a bilingual error in the status line instead of failing silently. It works from the document grid and from the `Enter` row popup.
- `e` edits a document in a JSON editor (`_id` immutable, field-level diff), `i` inserts, `Del` deletes by `_id` — every write confirmed, page reloaded in place.

**Empty states**
- Every empty list names its next step instead of leaving a dead end: the connection picker shows `no connections yet · c to create one`, an empty MongoDB page reads `no documents · f JSON filter · i insert a document`, and a zero-row result reads `0 rows · edit the SQL then Ctrl-J to run again` (or `f` / `Ctrl-R` for a browsed table). The Redis key browser and the no-table sidebar were already explicit.

**Efficiency & experience**
- `?` opens a context mini cheat-sheet from anywhere (top keys for the surface under the cursor, single screen, no scrolling); in the editor / command input, where `?` is a literal character, `F1` opens the same sheet. A second `?` (or `F1` on the mini sheet) opens the full cheat-sheet, and the footer adapts its hint count to the terminal width. The full sheet leads with a `— current context —` block (the surface's own keys first — in the results pane that is `v` / `Y` / `*`) and packs two key/description columns per line on wide terminals; below 56 columns it falls back to a single column. Press `/` inside it to filter by keycap or feature name in either language (a section name such as `Results` surfaces that whole group); `Enter` keeps the filter, `Esc` clears it. Every overlay closes with `Esc`.
- Number and count-prefix jumps: `1-9` jumps to the Nth connection/table, `3j`/`5n` repeat a move / page in the sidebar, results and history; on the results pane `gd` shows the structure, `gt` returns to the data, `gv` locates a value and `|` jumps columns.
- `Alt-1..9` jumps straight to the Nth connection (sidebar order) and `Alt-Tab` / `` Alt-` `` toggles between the current and previous connection (`Alt-Shift-H` lists this session's recent connections, `Enter` reconnects). A switch smartly restores the last database/table — a same-named one opens directly, otherwise the database list's first screen with a landing hint — and uncommitted editor text is flagged once, never silently dropped.
- With text selected (`Shift`+arrows) `Ctrl-J` runs only the selection (a selection always wins, for `F5` too); with no selection it runs the statement under the cursor, found by semicolon (a `;` inside a literal or comment never splits — the same lexer as the `%` bracket matcher; a caret parked in the gap between statements takes the next one). `F5` runs the whole editor and `Alt-Enter` is the cursor-statement shortcut. A scoped run **keeps the selection**, names what it ran in the status bar (`执行第 N 条` / `ran statement N`), and a failure localizes the red block to exactly those statements, with `F8`/`Shift-F8` cycling only this run — pure client-side slicing, zero extra queries. `Alt-P` opens saved snippets and pastes the pick at the cursor in one step (`Ctrl-O` still appends to the end).
- `Ctrl-A` auto-collapses unfocused panes and `Ctrl-W` pins one; below 50 columns the panes stack vertically. In the side-by-side layout the sidebar sizes itself to the widest `schema.table` name (never below a readable floor, and 28 columns are kept on a wide screen), so the data area keeps the freed columns; a name too long for the sidebar is cut and marked with `~`.
- `Alt-C` compacts column widths, `Alt-V` hides columns, `Alt-R` jumps to a recent table (the overlay's `s` toggles most-recent-first / by-name order), `Alt-H` opens the query history — choices persist per `database.table`.
- `Alt-←` / `Alt-→` walk the last 50 browsed nodes — SQL tables, MongoDB collections and Redis keys are all first-class stops (a value/document *detail* view is not, so a back step lands on the list entry that opened it); like a browser, the forward branch is dropped when you open a new node, and cross-database jumps work too. The status line confirms the landing with `← table`. The sidebar `t` overlay still lists the last five for a direct jump.
- Multi-statement output doubles as a console: `Home`/`End` and `gg`/`G` jump to the top / bottom of the statement list, `Enter` on an errored row opens the error box, `y` copies the focused statement's result as CSV (the format `Ctrl-Y` export leads with), and `Alt-O` toggles a separator line plus a compact per-statement timing prefix (`12ms`, `1.23s`) — off by default. (`Alt-T` is the data-transfer wizard, hence `Alt-O`.)
- Mouse and touch work: click selects, click again confirms; a **double click** (two presses at the same spot within 400 ms) opens the row detail — the mouse `Enter` — and tap-tap does the same on a terminal that never reports a button release. Inside the row-detail popup a click moves the cursor to that value and a double click drills into the full cell; the sidebar `▶`/`▼` glyphs fold and unfold a connection or database without selecting the row first; the confirmation layer's `[ Enter/y execute ]` / `[ Esc/n cancel ]` buttons are clickable (the `Enter` / `Esc` branches), the error box widens on a tap and pages through a long error, and a click in the editor focuses it and drops the caret where you clicked (honouring horizontal scroll; below the text jumps to the end). The wheel scrolls, `Shift`/`Alt`/`Ctrl`+wheel pans columns.
- Failures are visible: a watchdog turns a dead backend into an error, a spinner with elapsed seconds shows work in flight, and server errors echo verbatim.
- Large results stay smooth: a 20,000×12 grid scrolls at ~0.6 ms/frame (column widths are cached and only the visible window is sliced out, instead of re-scanning every row each frame), and file export runs on a background worker that streams straight to disk — 20,000 rows × 12 columns in well under a second, with peak memory near a single row (~36 MB whole-process, versus ~96 MB when the document was built in memory).
- All UI strings come from one table (`src/ui_text.rs`); Chinese is the default, `DBXT_LANG=en` switches to English.

## Installation

One-line script — bash (also Termux), or PowerShell:

```bash
curl -fsSL https://raw.githubusercontent.com/vst93/dbxt/refs/heads/master/cmd/install.sh | bash
```

```powershell
irm https://raw.githubusercontent.com/vst93/dbxt/master/cmd/install.ps1 | iex
```

China mirror: use `https://cdn.jsdelivr.net/gh/vst93/dbxt@master/cmd/install.sh` (or `.../install.ps1`) instead. The script reads the version from the GitHub release, verifies the `.sha256` and installs to `~/.local/bin` (`$PREFIX/bin` on Termux, `%USERPROFILE%\.local\bin` on Windows), reporting install / upgrade / already up to date. It keeps a newer local build instead of downgrading it. Options: `--force`, `--preview`, `--musl`, `--skip-github`, `--install-dir <dir>`, `--lang en|zh`, and the matching `DBXT_*` environment variables (`--help` lists them).

Every release attaches one archive per platform plus a `.sha256`:

| File | Platform |
| --- | --- |
| `dbxt-linux-amd64.zip` | Linux x86_64 (glibc) |
| `dbxt-linux-arm64.zip` | Linux ARM64 (glibc) |
| `dbxt-linux-amd64-musl.zip` | Linux x86_64 (static) |
| `dbxt-linux-arm64-musl.zip` | Linux ARM64 (static) |
| `dbxt-darwin-amd64.zip` | macOS Intel |
| `dbxt-darwin-arm64.zip` | macOS Apple Silicon |
| `dbxt-windows-amd64.zip` | Windows x86_64 |

Unzip and put `dbxt` on your `PATH`. The glibc builds link the CI runner's glibc; on older distributions prefer the static `musl` build. Android/Termux has no dedicated artifact — the static aarch64 build usually runs, otherwise `pkg install rust` and build from source.

From source (Rust 1.85+ and a C toolchain; the first build compiles the DBX kernel and several C dependencies):

```bash
cargo install --git https://github.com/vst93/dbxt
# or: git clone https://github.com/vst93/dbxt && cd dbxt && cargo build --release
```

Releases are cut from GitHub Actions: `gh workflow run release.yml` (optionally `-f version=0.2.0`) bumps the patch of the latest tag, tags, creates the release and builds all seven archives. `dbxt --version` and `dbxt --help` answer without opening the TUI. `dbxt [DBX_STORE] --last` reconnects the last session's connection and reopens its `database.schema.table` at startup (degrading one level at a time: table → database → connection → list).

## Quick start

1. Run `dbxt` — it reads the same store as DBX Desktop.
2. Pick a connection (`↑` `↓` + `Enter`), or press `c` to create one.
3. `Enter` on a table to browse it; type a letter in the sidebar to filter tables at once (`Enter` opens the first hit), `d` switches database.
4. `e` edits a cell, `i` inserts, `Delete` deletes — each shows the full SQL before it runs.
5. `F5` runs the editor's SQL; `?` opens a context mini cheat-sheet (`F1` in the editor, where `?` is a literal character; again for the full help).

For a database behind a bastion, press `c`, set `ssh_tunnel` to `y`, fill `ssh_host` / `ssh_user` and the login method, then `Enter` on the save row. The connection now goes dbxt → jump host → database.

## Persistence & configuration

Per-table choices (compact widths, hidden columns, sort) and remembered column widths (`<`/`>` in the results pane) are written to `~/.config/dbxt/tui.json`, keyed by `database.table` (a column width also carries the connection and column name, capped at 200 entries with LRU eviction); the connection / database / table the last run left off on is written to `~/.config/dbxt/last-session.json` (only after a connection actually opened) and reloaded at startup to highlight that connection, or to auto-resume it with `--last`; `DBXT_CONFIG` overrides the directory for both, `DBXT_LAST_SESSION` overrides just the session file, and `DBXT_NO_PERSIST=1` disables them. `DBXT_LANG=en|zh` selects the UI language (the locale decides when unset), `DBX_DATA_DIR` points dbxt at a different DBX store, and `DBXT_INSTALL_DIR` is the install script's target directory.

The SSH-tunnel unit tests (serialization shape, form mapping, auth/error classification, host-key prompt) run with the normal `cargo test`. Two extra end-to-end tests drive a real tunnel (dbxt → local `sshd` → MySQL) and are skipped unless `DBXT_SSH_TEST=1`; they read `DBXT_SSH_TEST_USER` / `_PASSWORD` / `_KEY`, `DBXT_SSH_TEST_MYSQL_PORT` (default 13306) and `DBXT_SSH_TEST_MYSQL_USER` / `_PASSWORD`. `tests/secret_store.rs` also runs with `cargo test`: it generates a throwaway `DBX_SECRET_KEY_FILE`, saves an encrypted connection and reads its password back (the key is never committed).

## DBX Secret Store compatibility

dbxt builds against **DBX v0.6.27**. From v0.6.27 the kernel encrypts connection / plugin / AI / tunnel secrets at rest (`dbxenc1` envelopes, AES-256-GCM) with a key that lives **outside** the database. dbxt does not manage that key — it passes the kernel's resolution straight through — so which store it can open depends on the key provider being reachable.

| Store state | What dbxt does |
| --- | --- |
| Plaintext (legacy, not yet upgraded) | Refuses to open with `DATA_MIGRATION_REQUIRED` and prints a hint: finish the **Data Security Upgrade** wizard in DBX Desktop (or Web) first. dbxt never migrates data and never bypasses the gate. |
| Encrypted, key reachable | Opens transparently; passwords and tunnel credentials decrypt as usual. |
| Encrypted, key unreachable | Refuses to open with `SECRET_KEY_UNAVAILABLE` and prints a hint pointing at the key sources below. |

**Key sources**, in the order the kernel resolves them:

1. `DBX_SECRET_KEY_FILE` — path to a key file (a 64-char hex or base64url 32-byte key, or a passphrase hashed with Argon2id). Best for headless / container hosts.
2. `DBX_SECRET_KEY` — the key material directly in the environment.
3. OS keychain — macOS Keychain, Windows Credential Manager, Linux Secret Service (compiled in via the `os-keyring` feature). This is where DBX Desktop stores the key.
4. `<data-dir>/.dbx/secret.key` — the managed per-user fallback.

A CLI/MCP process only *reads* the key: it never provisions one and never migrates legacy credentials. If you run dbxt without DBX Desktop, export the key (`DBX_SECRET_KEY_FILE`) so it can decrypt the store.

Version note: a dbxt built against the plaintext-era kernel (v0.6.9 and earlier) cannot read a store that DBX Desktop has already upgraded — upgrade dbxt alongside Desktop. The reverse also holds: the v0.6.27 kernel will not silently read a plaintext store; complete the wizard first.

## Status & roadmap

Early but usable. Verified end-to-end against real MySQL 8.4, PostgreSQL 16, Redis and MongoDB servers.

**PostgreSQL** — the SQL backend speaks the PostgreSQL dialect end to end. Identifiers are double-quoted (`"schema"."table"`, reserved words included); `bytea` (`0x…` cells round-trip as `'\x…'::bytea`), `uuid`, `jsonb`, arrays (`ARRAY[…]`) and enums render in full and copy/export as valid SQL; `serial` / identity columns are skipped by the insert template so the sequence stays authoritative; and `Ctrl-P` issues a plain `EXPLAIN` (never `EXPLAIN ANALYZE`), so a write statement is planned without being executed. Structure and DDL read `pg_catalog` with an `information_schema` fallback, and the DDL resolves the relation's visible schema (`CREATE TABLE "public"."accounts"`, plus indexes, constraints and comments). Browsing is schema-aware: `d` lists the database's schemas (schemas first, then databases), the sidebar shows `inv.items`-style qualified names, and table data, structure, DDL, cell edits, inserts, deletes, filters, sorts, CSV import/export and INSERT export all carry the selected schema — so `public.orders` and `inv.orders` never mix. Column visibility, the saved sort and the `COUNT(*)` cache are keyed by `database.schema.table`.

- [x] SQL browsing, editing, transactions, filter/sort, completion, CSV import/export and result tabs
- [x] Redis key browser with batch key operations
- [x] MongoDB document browser with document CRUD
- [x] SSH tunnels (password / key / agent, `~/.ssh/config` aliases and `ProxyJump`) with in-TUI create/edit
- [x] Prebuilt archives for seven targets — only the Linux x86_64 build has been exercised locally, the others are untested
- [x] In-TUI connection deletion (red confirmation; config only, never database data)
- [ ] Result export to XLSX, and search across pages
- [ ] Excel (`.xlsx`) import
- [ ] A dedicated Android/Termux build

## Known issues

An honest list of what is **not** there yet, so it is not discovered after a release.

- **Table size metadata is MySQL / PostgreSQL only.** Pressing `s` on a database row reports *this engine does not support size query* on SQLite, DuckDB and any other engine — the sidebar size column stays empty there.
- **Global search (`Alt-G`) is MySQL / PostgreSQL only** — it scans the `char` / `varchar` / `text` columns of every table and is not wired to other engines.
- **No `.xlsx` import and no XLSX export** — deliberately out of scope; use CSV.
- **Search is page-local** — `/` searches the visible rows, not the whole result set; cross-page result search is not implemented.
- **A large export is capped by a warning, not stopped** — result sets over 10,000 rows warn before `Ctrl-Y` proceeds.
- **Read-only detection fails closed** — a statement with an unrecognised verb counts as a write, so a rare ambiguous-but-read statement is refused by design.
- **Redis / MongoDB are out of scope** for the `Alt-T` transfer wizard and for the `Alt-D` / `Alt-K` schema & data diff.
- **Only the Linux x86_64 prebuilt archive has been exercised locally** — the other six build in CI but are untested.
- **No dedicated Android/Termux artifact** — the static aarch64 build usually runs; otherwise build from source.
- The connection tree reads the desktop group layout **once per session**, so a regrouping in DBX Desktop shows up the next time dbxt opens.
